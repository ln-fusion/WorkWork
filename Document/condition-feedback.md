# 条件联动高亮（2026-10-17）

已实现：效果发动时，被计入当前条件的对象同时短暂亮起，再显示原有得分或倍率飘字。采用淡金色边框与浅底光，不改变卡牌本身的颜色、位置或缩放，不增加文字。

## 覆盖范围

- 花色数量、同花加分：只标记符合当前花色的场上实体牌，例如客服的红桃、美术加工后的梅花、各花色概要与“同花加分”的同花色牌。
- 点数、同点数与奇偶：按当时实际点数匹配。土豆、冲锋枪等前置改点后的后续效果读取改后的值，不使用本轮开始前或整轮结束后的值。
- 附魔数量条件：营销读取带“粉丝”的牌、社群读取带“同花加分”的牌、数值读取自身附魔等。每个实体目标只亮一次，不按附魔种类重复闪。
- 相邻同色：只亮本工位及紧邻、符合条件的牌，不跨空位寻找，也不标记远处同色牌。
- 全红、全黑、全奇、全偶、满6牌、点数总和与最高点数比较：仅实际满足并产生收益时标记参与检查的牌。四花色计数每种取一张代表，不把重复花色重复表现成另一种。
- TNT读取本次最初判定的牌型。四条标记最初四张同点牌，四带对标记最初六张；即使后续改点，也不根据改后的牌面另选目标。已被斩断的牌不重新亮起。
- 员工数与道具数：亮对应员工图像或道具图像，例如人力资源、采购、员工数量道具和供应链的3装备倍乘。
- 行政的空位：先播放删牌，再亮实际为空的卡槽，避免牌还在画面上就提前显示为空。

固定加分、现金存量、重抽历史、历史牌型数量、隐藏牌库规模等没有对应当前可见牌的条件，不随意亮全场。生成、复制、删除、附魔加工仍走各自已有动画，不把动画替身当作额外参与目标。

## Inspector

**WorkWork MVP → Condition Feedback**：

| 参数 | 默认值 | 作用 |
| --- | --- | --- |
| Duration | 0.2秒 | 一次亮起淡出的总时间 |
| Border Width | 3 | 边框宽度 |
| Fill Alpha | 0.14 | 浅底光最大透明度 |
| Highlight Color | 淡金色 | 边框和底光颜色 |

同一步所有目标并行，不逐张等待。WorkWork/Configure Condition Feedback用于组件缺失时装配，已有参数不重置；完整UI生成链也已包含装配，不为调效果重建UI。

## 数据与顺序

- Core在实际效果分支里记录参与对象，ScoreStep携带linkedCardIds、linkedEmployeeSlots、linkedItemSlots、linkedEmptySlots。不存在根据展示文案猜测条件的逻辑。
- 元数据按步骤独立去重，步骤结束清空待记录目标，条件失败或本步得分/倍率没有变化不发高亮，不把上一步目标泄漏到下一步。
- GameController保留原来源跳动；有目标的步骤先完成牌面/附魔变化及必要的删除，再等待ConditionFeedback.Play，随后显示收益和更新结算数字。ScoreFeedback的来源动作与飘字可分别执行，避免同一步跳两次。
- ConditionFeedback使用独立不可交互覆盖层，每帧跟随目标的实际位置与旋转，不写原卡牌颜色。缺失目标及已删除牌跳过，目标都不可见时不额外等待。
- Clear/CancelScoring/停用清理覆盖层，不修改规则、随机状态或入账。新规则若要联动，应在实际条件分支补充参与对象记录。
