# 局域网联机开发计划（讨论稿，2026-10-15）

## 已确认与待定

已确认：同一局域网连接，玩家电脑兼任房主服务器，不接Relay/云房间码；先联机、后完整动画；保留单机模式和手调UI，资源便于替换；MCP断开要告知用户。

本文件是开发思路与目标表现，不代表已实现或已确认全部范围。玩家人数、合作/各自经营、共享资源、操作权限、推进周/月条件、断线与存档规则待下一轮玩法讨论。首版不自动加入血量或扣血机制。

## 技术结构

保留Unity 2022.3.62f3。NGO（Netcode for GameObjects）+ Unity Transport为建议技术栈，安装时核对兼容包元数据并锁版本，暂不升级Unity。此计划阶段不安装依赖。

- Core：纯C#规则层，GameSession执行随机、操作校验和计分，不引用网络或UI。
- Network：独立网络适配层，负责连接/玩家身份/请求/状态同步/断线通知。
- Runtime UI：接收输入、发送操作请求、呈现允许本玩家看到的状态。
- 后续动画：根据有顺序的事件播放；状态正确性不依赖动画完成。

房主同时运行规则端和自己的显示端；其他客户端只能提交请求。房主自己的操作也走相同的校验入口。单机通过本地适配走同一规则入口，不强制建立网络连接。

同步卡牌ID、点数、花色、附魔、员工/道具ID、资金、阶段和任务等业务数据；不逐个联网同步Canvas、Image和RectTransform。鼠标悬停、拖拽影像、帮助/设置属于本地表现。

## 开发顺序与阶段验收

### 1. 基础连接原型（玩法讨论前也可独立开发）

安装兼容网络包，建立独立网络模块和测试入口。实现创建局域网房间、输入IP/端口加入、连接状态、玩家列表、离开和停止房间。房主显示局域网地址，支持修改端口。

先IP直连；自动搜索局域网房间为后续体验增强，不阻塞基本连接。UI沿用现有字体、PhonePanel、原生Button反馈；新增节点方便Inspector手调，不整场景重建。

验收：编辑器+独立程序互连；两台电脑互连；能交换测试消息，连接失败/离开后能再次创建加入。检查防火墙、网卡和Wi-Fi访客隔离问题，不自动关闭防火墙。

### 2. 明确多人玩法与状态归属

确定人数、经营方式、共享/私有数据、谁操作谁的卡、周/月推进条件、商店与任务归属、掉线和存档规则。形成玩家ID到状态/权限的映射，再接入实际玩法，避免提前锁死合作或独立经营。

### 3. 统一操作入口，接通房主执行

梳理目前UI直接修改Session的入口，替换为提交类型明确的操作请求：放牌/收回/换位/重抽/计分/购买/出售/刷新/员工与装备换位/任务选择/进入商店与下月等。

房主校验连接身份、权限、阶段、对象ID、资源和请求编号；拒绝非法、重复或过期请求。将结果和状态版本发回客户端。保留现有单机测试与本地入口。

验收：一次操作只能生效一次，失败不扣钱、不丢牌；客户端不自行随机、不自行发奖金。

### 4. 同步完整游戏闭环

加入或开始时发送本玩家允许看到的初始快照，之后有效操作发送更新；初期优先清晰可靠，可使用体积受控的视图快照，再按实际需要拆增量。消息使用适合规则状态的可靠有序传输，并处理长度限制、必要的分片/重组。

不能直接广播存档对象：存档可能含私有手牌、隐藏牌库顺序和随机状态。根据玩法制作公开/私有视图；校验游戏协议和规则配置版本一致，防止两端效果不同。

覆盖周结算、月末胜负、商店、附魔、复制牌、任务发放四选一、期限和一次性奖金。客户端纯显示与输入，房主为权威。

验收：双方显示各自应见的相同事实，跨周/月不分叉；未选择任务不能绕过阶段；共享商品等冲突由房主按确定顺序处理。

### 5. 房间异常与存档规则

连接超时、拒绝连接、版本不符、客户端离开、房主离开都给明确提示并清理网络状态。房主/客户端是否暂停、允许重连和何时重连、是否允许中途加入、存档由谁保存，按玩法讨论结果实现。

首版建议：房主退出结束房间，不做自动房主迁移；先限制进行中加入，后续再加断线重连。均为建议，尚未作为用户确认规则。

### 6. 双机回归与后续动画

保留单机完整功能，跑规则回归、连接与消息测试；独立打包并真实双机长流程验证。覆盖同时操作、反复进入退出、满员、异常断开、存档、跨多月和任务周期。

完成联机后，再做逐牌计分、附魔触发、奖金到账和月末动画。提前输出带顺序和状态版本的结构化事件；动画按事件播放，可快进/跳过，最后对齐权威状态。

## 玩家最后看到的表现（目标）

- 原单机入口继续使用；联机有独立的创建/加入入口，具体放在欢迎界面哪里随UI讨论确定。
- 创建后看到房主地址、玩家列表和状态；其他玩家输入地址加入。房主可开始游戏，是否要求所有人准备由玩法决定。
- 进入游戏后继续使用现在的牌桌、商店、任务、右键详情与音乐；显示联机身份/连接状态，操作权限由规则限制。
- 点击和拖拽的本地反馈立即出现；真正的落牌、购买、抽牌和结算得到房主确认后显示最终结果。
- 结算/等待阶段给清楚状态，避免重复提交；另一端能看到玩法允许公开的变化。
- 出错显示原因和返回路径，不停在无响应界面。房主退出行为按最终规则处理。

## 下一轮玩法对齐清单

1. 几名玩家？合作经营一家，还是各自经营？
2. 牌库、手牌、工位、员工、装备、资金、商店分别共享还是独立？
3. 能看见哪些别人的信息，能操作哪些位置？
4. 谁能重抽、计分和推进周/月？各自准备后统一推进，还是其他方式？
5. 月度目标、胜负、任务四选一和奖金归谁？
6. 玩家退出/断线后怎么继续，存档和恢复怎么处理？
