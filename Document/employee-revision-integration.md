# 员工第二版接入记录（2026-10-16）

用户修改 employee-effects-v2.md 后授权应用。33名员工的名称、价格、效果说明、持有附魔和特殊结算均按该稿配置，不是仅替换说明文字。

## 最新确认与用户修改

- 客服每张红桃+4倍率；美术每张梅花+20基础分。
- 游戏测试按本月成功执行重抽的次数，每次+10基础分；用户明确跨月清零。失败重抽、单纯获得重抽次数、预览及重复播放均不累计。
- 运营每次结算生成6张0点牌，场上每张0点+20基础分；校对每月补6张0点牌。
- 法务随机删除至多2张合法无附魔低点牌，不沿用优先最低点数；行政先自行删0至2点牌，再读取空位与规模，精简奖励+5倍率。
- 客服全红桃“金币”、文案全3点“粉丝”、财务全方片“金币”、界面全2点“点数翻倍”、营销全2点“粉丝”、社群全黑桃“同花加分”、市场经理全6点“金币”。测试与程序的“重抽”“复制”保持精准花色和点数。
- 音乐自行添加“同花加分”并先额外结算该附魔，再读取邻牌同色奖励；商务先按左邻优先改色，再读取邻牌条件。
- 活动每次员工结算直接复制本工位1张，不要求有“复制”附魔；副本不继承“复制”，不当成场上第二张牌。使用现有复制上送动画，事件来源为员工。
- 数值随机添加尚未拥有的普通附魔，包含“双倍”，然后按种类奖励；动画先添加“点数翻倍”再额外计分，不额外触发“复制”“重抽”，无牌不再给旧版30分。
- 供应链有本工位牌才生成同花色1点牌，先生成后读取规模，任意3件装备即可倍乘，不再限定同名；无牌仍处理规模和装备条件。
- 关卡只把有另一张同花色的本工位牌改成缺失花色，不减少已有花色种类；缺失多种时采用红桃、方片、梅花、黑桃的确定顺序。
- 引擎先转黑并升1点，再判断唯一最高；技术美术先自行改色再加“粉丝”，不再依赖旧版每牌每员工每月一次标记。
- 游戏发行在总和小于21时给40基础分，包含全0与本工位无牌；大于21不触发，等于21倍乘。

## 配置和资源入口

1. 员工源：Document/employee-effects-v2.md。第一版 employee-effects-draft.md 只留历史。
2. 运行 node Document/build-content-source.cjs，生成 Assets/WorkWork/Config/ContentDefinitions.json。该脚本仍同时生成道具与任务的可审阅源，但生成文件本身不改实时目录。
3. Unity菜单 **WorkWork → Apply Employee Revision** 只替换 GameCatalog 中33名员工。保留当前目标曲线、初始资金、牌组份数、37件道具、任务、图片映射及场景/预制体。
4. 原 WorkWork → Apply Final Content 仍是首次/全量内容导入，会覆盖内容与默认目标曲线；员工单独调平不要使用它。
5. 实际执行员工导入前后，非员工规则及主题的序列化摘要完全一致。当前Inspector初始目标为400、Deck Copies为2，已保留，未回写成内容源默认600。

Values的主要新含义：游戏测试Chips为每次重抽基础分；运营Count为每周生成数、Chips为每张场上0点基础分；校对Count为每月补0点数量；活动Count为直接复制数；供应链Count为生成1点数；市场经理Count为生成6点数。其他字段继续按对应岗位说明读取。

## 规则、存档与确定性

- 结算在完整状态快照上计算一次，动画之后提交原快照；随机附魔、生成花色、法务目标和复制不因预览/动画多执行。
- 附魔刷新保留仍有效的既有附魔，清除失效或售出来源，再按招聘顺序填空槽。不会因全量重建持有附魔，把后加工的附魔挤进原有位置或错误挤掉旧种类。
- 改色和改点立即刷新持有附魔资格，不追溯已结束的牌面阶段；后续小夜灯可以读取加工后的附魔。员工主动赋予的来源在售出时清除，和其他同种来源合并保留。
- 校对和玩法共用按员工、经营月份登记的补牌队列。月末商店招聘先登记下一经营月，月初基础重建后补牌；同月售出重买、存档再读不重复。已登记补牌不因出售丢失。
- 旧 pendingSevenMonths 自动迁移到 pendingMonthlyCards；旧存档在经营中持有校对时，为当前月补发新能力份额一次，保留当前周次、分数及牌组，不重建当前月份。技术美术旧月内标记仅作为旧存档兼容字段保留，不再控制赋予。
- 读档不改已有目标和已接受任务快照；本次未主动覆盖用户存档。新规则对现有员工生效，后续月初照常重建牌组并按持有员工赋予。
